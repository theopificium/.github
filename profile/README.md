## Engineering principles

| | Principle | Meaning |
|---|---|---|
| `01` | **Precise** | Clear contracts, explicit behavior and measurable outcomes. |
| `02` | **Modular** | Components have boundaries and can evolve independently. |
| `03` | **Crafted** | APIs, DX, naming, documentation and failure modes matter. |
| `04` | **Engineered** | Reliability and scalability are designed into the system. |
| `05` | **Open** | Prefer understandable systems, portable standards and useful documentation. |

## Build standards

**Architecture** — separate domain decisions from framework details.  
**Interfaces** — keep contracts explicit and versionable.  
**Delivery** — automate repeatable work and keep deployments reversible.  
**Quality** — test behavior at the correct boundary.  
**Documentation** — record decisions that cannot be inferred from code.  
**Security** — treat trust boundaries, secrets and dependencies as architecture concerns.
